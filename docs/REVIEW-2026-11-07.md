# Review — variant removal failure, route map, admin buttons

> Verified against disk: 2026-11-07 @ 6294d17 + working tree (uncommitted fix). Point-in-time report; not maintained after its date.

## 1. Bug: removing a variant fails with "URL gambar produk tidak valid."

**Symptom.** Removing a variant in the product form and saving returns the error above.

**Root cause.** `PATCH /api/admin/products` re-validates the *whole* product, including `image_url`, on every save. `parseProductMutationPayload` (`src/lib/product-mutation.ts`) only accepts `/assets/uploads/…` or `/images/…`. A row whose stored `image_url` has any other shape (an absolute `https://` URL, `/media/…`, or similar) is loaded into the form, sent back unchanged, and rejected. The user did not touch the image, so the error looks unrelated to the action.

**Fix.** The PATCH handler reads the stored `image_url` and passes it to the parser as `storedImageUrl`. A value identical to the stored one is not re-judged. Any *changed* value is still checked against the allowlist, so the trust boundary is unchanged for new input.

- `src/lib/product-mutation.ts` — new optional third parameter.
- `src/pages/api/admin/products.ts` — one `SELECT image_url` before parsing.
- `src/lib/product-mutation.test.ts` — new test: a legacy value is accepted only when it equals the stored one.

**Evidence.** `npm test` 1194 pass / 0 fail (baseline 1193 + 1). `npm run check` 0 errors / 0 warnings / 0 hints.

**Browser evidence (local `dev:local --reset` + `dev:seed`, 2026-11-07).** Product 34466 was set to `image_url = https://cdn.example.com/kaos.jpg` (outside the allowlist). In `/admin/products/edit?id=34466` I removed variant 3 and pressed *Simpan Produk*: redirected to `/admin/products`, D1 afterwards holds variants S and M, `image_url` unchanged. I did **not** run the same steps against the pre-fix code, so the "before" failure is shown only by the unit test.

**Not done / open.**
- Confirm on the install that showed the error which `image_url` its product has.
- Rejected shapes also include absolute `https://` URLs. If merchants legitimately paste CDN URLs, widen the allowlist deliberately (ADR) instead of relying on the stored-value escape.
- The error text does not name the field's origin. Consider a clearer message for the form.
